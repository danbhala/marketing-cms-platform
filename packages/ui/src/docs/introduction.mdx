# Marketing UI

A CMS-agnostic component library for marketing websites, built on shadcn
(`base-nova` style, Base UI primitives) and Tailwind CSS 4.

## Layers

| Layer      | Folder           | What lives here                                                                       |
| ---------- | ---------------- | ------------------------------------------------------------------------------------- |
| Tokens     | `src/styles`     | shadcn semantic CSS variables, theme classes, block spacing variables                 |
| Primitives | `src/primitives` | Vendored shadcn components (Button, Card, Accordion, Tabs, …). Not edited by hand.    |
| Atoms      | `src/atoms`      | Typography (one CVA scale), Section, Container, Stack/Grid, Icon, Link, Image, Button |
| Molecules  | `src/molecules`  | Repeatable units inside blocks: SectionHeader, FeatureItem, Quote, PriceCard, …       |
| Blocks     | `src/blocks`     | The 17 marketing sections a CMS author can place on a page                            |
| Templates  | `src/templates`  | Announcement bar, header, footer and the PageTemplate that renders a CMS page         |

## How blocks relate to the CMS

Every block takes a `block` prop whose type comes from
`@platform/content-model`. That package defines each block's fields once and
generates the schema for every CMS, the TypeScript types and the zod
validators. The sample content in these stories comes from
`@platform/content-model/fixtures`, the same data the local CMS and the docs
site use.

Blocks never import a CMS SDK or a framework. Links and images go through
`UiProvider`, which the Next.js app fills with `next/link` and `next/image`;
Storybook uses plain `<a>` and `<img>`.

## Visual editing

In draft mode an adapter attaches `$edit` metadata to each block and item.
Components spread it with `editAttrs(block)` and `fieldAttrs(block, "title")`
so a CMS's live-preview overlay can find the element. In production the
helpers return `{}` and nothing is rendered.

## Working in Storybook

- **Theme toolbar** (paintbrush icon) switches the same `theme-*` classes the
  app uses. See [Theming](?path=/docs/docs-theming--docs).
- **Accessibility** runs on every story and fails the test run on violations.
- `pnpm test` runs the unit project and the Storybook browser tests.
