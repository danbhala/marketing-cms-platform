## Environment

`STORYBLOK_PREVIEW_TOKEN` (required, preview scope), `STORYBLOK_REGION` (`eu` default), `PREVIEW_SECRET`, `REVALIDATE_SECRET`; optional `STORYBLOK_PUBLIC_TOKEN`, `STORYBLOK_SPACE_ID`, `STORYBLOK_WEBHOOK_SECRET`, `STORYBLOK_TRANSLATED_SLUGS`. See `apps/web/.env.example`.

## Push the content model

```bash
pnpm --filter @platform/cms-storyblok schema:generate   # writes schema/components.json
npx storyblok login
npx storyblok push-components packages/cms-storyblok/schema/components.json --space <id>
```

The generated files are committed under `packages/cms-storyblok/schema/` so diffs show exactly what changes in the CMS when the content model changes.

## Preview

Settings → Visual Editor: preview URL `https://your-site/api/preview?`. The editor appends `_storyblok`, `_storyblok_tk[...]` and `_storyblok_lang`; the adapter validates the token (`sha1(space_id:preview_token:timestamp)`, one-hour window), resolves the story id to its path, and the app enters Draft Mode. Hand-made previews: `/api/preview?secret=<PREVIEW_SECRET>&path=/pricing`.

Inside the editor every document, block and item carries `storyblokEditable()` attributes (`data-blok-c`, `data-blok-uid`); Storyblok targets whole bloks, so there are no field-level attributes. The bridge loads `@storyblok/js`'s preview bridge and refreshes the page on `input`, `change` and `published`.

See [Preview & visual editing](/docs/preview) for the shared flow.

## Webhook

Settings → Webhooks → story events → `https://your-site/api/revalidate` with a secret. Storyblok signs the raw body with HMAC-SHA1 in `webhook-signature`. Tags: `cms:entry:<story_id>` always; pages add `cms:page:<locale>:/<full_slug>` and, on publish/unpublish/delete/move, `cms:paths:<locale>`; the `site-settings` story maps to `cms:global:<locale>`.

## Listings

`getCollection` is one `cdn/stories` request with `content_type=article`, `sort_by` (`content.publishedAt:desc`, `content.publishedAt:asc` or `content.title:asc`), `page`/`per_page`, `search_term` for free-text search and `resolve_relations=article.category,article.tags` so terms come back inline. The total is read from Storyblok's `total` response header. Filters are term slugs, so the adapter fetches the `category` stories, maps slugs to UUIDs and sends `filter_query[category][in]` (single reference) or `filter_query[tags][any_in_array]` (multiple); an unknown slug returns an empty page without a stories request. Draft Mode reads `version=draft` and attaches editor attributes to every item. `getTaxonomy("category")` returns every category story, `getDocument` dispatches on the story's component (`page` or `article`), and `getPaths` lists both.

Languages use field-level translation: the site's default locale is the space's default language and every other locale is passed as `language`. With the Translatable Slugs app, set `STORYBLOK_TRANSLATED_SLUGS=true`: each language's pages are then read by their own slug behind a language prefix (`fr/a-propos`), `getPaths` lists them, and `getTranslatedPaths` reports them from the story's `translated_slugs` and `default_full_slug`. The home story is `/` in every language.

Articles and categories are root stories of the generated `article` and `category` components; the story slug is the URL path of an article and the filter slug of a category, so neither has a `path` or `slug` field. `publishedAt` is a `datetime` field; `category` and `tags` are `option`/`options` fields fed by `internal_stories` and stored as UUIDs. Story webhooks carry no content type, so every story event also refreshes `cms:collection:<locale>:article`, `cms:type:article` and `cms:type:category`.

## Mapping notes

- Pages are stories of type `page`; `full_slug` is the URL (`home` → `/`), so the page `path` field is not in the Storyblok schema.
- Site settings is one story at `site-settings`.
- Document ids are the numeric story id (what webhooks and the editor carry), nested bloks use `_uid`.
- `textList` fields become a `bloks` field restricted to a generated `textItem` component.
- `date` values (`YYYY-MM-DD HH:MM`) become ISO strings; date-only values stay as they are.
