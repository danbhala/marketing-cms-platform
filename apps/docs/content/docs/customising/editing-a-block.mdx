---
title: Editing a block
description: "Change an existing block's markup, classes or behaviour, and keep it working in every CMS and in preview."
---

A block is one file in `packages/ui/src/blocks/`. It takes the canonical content as `block` and renders it with atoms and molecules. Open it and edit it; there is no override layer to learn first. This is the whole Stats block:

```tsx title="packages/ui/src/blocks/stats.tsx"
import type { StatsBlock } from "@platform/content-model"
import { fieldAttrs } from "@platform/cms-core/edit"

import { Container } from "../atoms/container"
import { Grid } from "../atoms/layout"
import { SectionHeader } from "../molecules/section-header"
import { StatItem } from "../molecules/stat-item"
import { cn } from "../lib/utils"
import { BlockItem, BlockSection, type BlockComponentProps } from "./block-section"

export type StatsProps = BlockComponentProps<StatsBlock>

function Stats({ block, index, className, ...props }: StatsProps) {
  const columns = block.columns ?? "4"
  const divide =
    columns === "2" ? "section-sm:divide-x" : columns === "3" ? "section-md:divide-x" : "section-lg:divide-x"
  return (
    <BlockSection block={block} className={className} {...props}>
      <Container className="flex flex-col gap-(--block-header-gap)">
        <BlockItem block={block}>
          <SectionHeader
            eyebrow={block.eyebrow}
            title={block.title}
            description={block.description}
            as={index === 0 ? "h1" : "h2"}
            source={block}
          />
        </BlockItem>
        <Grid columns={columns} className={cn("divide-border", divide)} {...fieldAttrs(block, "stats")}>
          {block.stats.map((stat) => (
            <BlockItem key={stat.id} block={block}>
              <StatItem
                item={stat}
                countUp={block.countUp ? { duration: block.animationDuration, delay: block.animationDelay } : null}
                className="px-4"
              />
            </BlockItem>
          ))}
        </Grid>
      </Container>
    </BlockSection>
  )
}

export { Stats }
```

## What you can change freely

- **Markup and classes.** Swap `Grid` for a flex row, add a divider, change paddings. Prefer the `section-*` container variants and the spacing tokens (`gap-(--block-header-gap)`, `py-(--section-space-md)`) so the block keeps following the theme, but nothing breaks if you use plain Tailwind.
- **Which molecules it uses.** `StatItem`, `SectionHeader`, `ActionGroup`, `ContentCard` and the rest live in `packages/ui/src/molecules`. Edit them to change every block that uses them, or copy one into the block file to change it in one place.
- **Defaults.** `block.columns ?? "4"` is where the fallback lives when an editor leaves the field empty. The CMS default comes from `defaultValue` on the field; keep the two in step.
- **Where the heading goes.** `SectionHeader` is only a convenience. Render `Eyebrow`, `Heading` and `Text` yourself when the layout needs it (the CTA block does), keeping `fieldAttrs(block, "title")` on whatever element shows the title.

## What to keep

| Keep                                                                                              | Because                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BlockSection` as the root, with `block={block}` and `{...props}` spread onto it                  | It applies `theme`, `spacing` and `anchor`, stamps `data-block`, and spreads the block's edit attributes so editors can select the whole section. Spreading `props` is what lets a wrapper pass `className` or `data-*` through. |
| `fieldAttrs(block, "<field>")` on the element that renders each field                             | Click-to-edit in Contentful, Storyblok, Optimizely, Sanity, Drupal and Wagtail all key off these attributes. They are `{}` outside draft mode, so they cost nothing in production.                                               |
| `key={item.id}` and `editAttrs(item)` on repeated items                                           | Same reason, one level down. The molecules already do this.                                                                                                                                                                      |
| `BlockItem` around the header and each item                                                       | It is what the `animationStagger` field reveals one by one. With stagger off it renders no extra markup, so it costs nothing to keep.                                                                                            |
| `as={index === 0 ? "h1" : "h2"}` on the title                                                     | Every page gets exactly one `h1`.                                                                                                                                                                                                |
| Imports limited to `@platform/content-model`, `@platform/cms-core/edit` and the UI package itself | `pnpm lint` fails on CMS SDK imports in `packages/ui`; Next imports would break Storybook and the tests. Use the `Link` and `Image` atoms.                                                                                       |

## Check it

The block's story in `stats.stories.tsx` renders it with the shared fixture, and `pnpm test` in `packages/ui` runs every story in Chromium with axe. If you changed colours or contrast on a themed variant, that is where it fails. `pnpm storybook` shows the result at `/?path=/docs/blocks-stats--docs`, and the [block pages](/docs/blocks/stats) in these docs render the real component too.

## Removing a block

Teams rarely need all twenty. Delete the block from `allBlocks` in `content-model/src/definitions/blocks.ts`, from `blockComponents` in `ui/src/blocks/index.ts`, from `allBlockFixtures` and from `types.ts`, then run `pnpm schema:generate`. TypeScript points at each remaining reference. `BlockList` skips block types it has no component for, but adapters differ on entries of a type that is no longer in the model: Contentful warns and skips, Optimizely throws. Remove or migrate the content in the CMS as part of the same change.
