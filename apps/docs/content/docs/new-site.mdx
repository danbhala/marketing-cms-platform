---
title: Start a new site
description: "One command copies the platform into a plain Next.js project that your team owns."
---

```sh
npx create-marketing-cms-app my-site --storyblok
```

The command runs the official [`create-next-app`](https://nextjs.org/docs/app/api-reference/cli/create-next-app) (its own prompts still apply; TypeScript, App Router, Tailwind, ESLint, React Compiler and Cache Components are fixed because the site depends on them), adds shadcn with `shadcn init`, then installs the `site-storyblok` item from this site's registry (`/r/site-storyblok.json`). Nothing is installed as a platform package: blocks, templates, the content model, the Storyblok adapter and the routes are all copied in as source.

It asks whether the site is in more than one language, which languages, and which is the default; the answers go into `locales` and `defaultLocale` in `cms.config.ts`. A one-language site gets `localePrefix: "as-needed"`, so its URLs have no locale (`/about`, and `/en-GB/about` redirects there); a multilingual one keeps the locale in every URL (`/fr/about`). `<html lang>` is the page's locale either way. Pass `--languages en,fr --default-language en` to skip the questions, and anything after `--` straight to create-next-app.

Storyblok is the only CMS in this version.

## Then

```sh
cd my-site
# in .env.local: STORYBLOK_SPACE_ID, STORYBLOK_PREVIEW_TOKEN, STORYBLOK_MANAGEMENT_TOKEN (a personal access token)
npm run cms:push   # creates every block and field in the space from lib/content-model
npm run dev        # http://localhost:3000/en
```

Run `cms:push` again after changing a definition.

## What lands where

| Path                                                      | From                           |
| --------------------------------------------------------- | ------------------------------ |
| `app/`, `cms.config.ts`, `proxy.ts`, top-level `lib/*.ts` | `apps/web`                     |
| `components/`                                             | `@platform/ui`                 |
| `lib/content-model/`                                      | `@platform/content-model`      |
| `lib/cms-core/`                                           | `@platform/cms-core`           |
| `lib/cms-storyblok/`                                      | `@platform/cms-storyblok`      |
| `lib/animation/`                                          | `@platform/animation`          |
| `lib/component-registry/`                                 | `@platform/component-registry` |

`next.config.ts` stays create-next-app's own, with `typedRoutes` and the CMS's image host added. `components.json` points the `ui` alias at `components/primitives`, so `npx shadcn add <component>` lands next to the site's own primitives. The demo content, the theme editor and the other CMS adapters stay in the monorepo.

## Maintaining the registry

`packages/registry/build.mjs` builds the registry from the monorepo on every docs deploy, rewriting `@platform/*` imports to `@/…` paths. `node packages/registry/smoke.mjs` scaffolds a site from a local copy of the registry and checks it lints and compiles; CI runs it on every pull request.
