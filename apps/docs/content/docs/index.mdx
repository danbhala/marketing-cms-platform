The platform is one front-end contract for every CMS: the same blocks, templates, preview, sitemap and caching, with an adapter doing the CMS-specific work. Each client site owns all of that as source code, so the team can add or remove fields and blocks without waiting on anyone.

## Quick start

```sh
npx create-marketing-cms-app my-site --storyblok
cd my-site
# fill in STORYBLOK_SPACE_ID, STORYBLOK_PREVIEW_TOKEN and STORYBLOK_MANAGEMENT_TOKEN in .env.local
npm run cms:push   # creates the blocks and fields in your space
npm run dev
```

Storyblok is the only CMS the CLI sets up so far; the other five adapters run in the monorepo. [Start a new site](/docs/new-site) walks through each step, including the keys, the first content and live editing, and the [CLI reference](/docs/cli) lists every option.

To see the result first, the [demo site](https://marketing-cms-platform-demo.vercel.app) runs the same code on sample content.
